\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}

Increasingly heterogeneous hardware, including CPUs, GPUs, and accelerators, often relies on shared-memory interfaces to access and exchange data. However, different architectures can allow different shared-memory behaviors, so the same concurrent program may behave differently across hardware. Memory models describe these behaviors by specifying which memory values each thread is allowed to observe. To reason about these behaviors more reliably, we need precise descriptions of the memory models. Empirical testing can expose some behaviors, but it cannot characterize all possible executions. Formal reasoning provides a more precise foundation, but their pen-and-paper proofs are difficult to check, reuse, and maintain.

Mechanization addresses these limitations by encoding memory model definitions and proofs in a proof assistant, where they can be checked by a computer. However, building mechanized developments requires additional effort. We present \textsc{LeanCat}, a domain-specific proof framework for mechanized reasoning about memory models in Lean 4. \textsc{LeanCat} builds on Mathlib and existing memory-model specifications and provides reusable definitions, abstractions, and proved lemmas for reasoning about weak memory models. It supports applications such as comparing the strength of different memory models, proving instruction-mapping correctness between architectures, and designing memory models for systems that combine devices with different memory models. \textsc{LeanCat} therefore provides a practical foundation for verified reasoning about weak memory models, with implications for compiler validation and cross-platform correctness guarantees.
